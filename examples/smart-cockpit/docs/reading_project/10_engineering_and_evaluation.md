# 10 · 工程装配与评测

理解功能后，还需要回答两个问题：项目怎样真正运行起来，以及怎样判断工具调用是正确、快速且可维护的。这一篇把启动、扩展、软件测试和模型评测连接起来。

## 四个服务怎样装配

原项目使用 Node.js 运行 Service、后台 Agent 和 Gateway，React / Vite 运行浏览器客户端。启动脚本先加载示例配置并进行预检，检查所选 Realtime 服务配置、后台模型凭据和端口，再并行启动四个进程。Gateway 启动前还等待 Service 就绪，以便发现前台工具。

| 进程 | 默认本地端口 | 配置与连接对象 |
|---|---:|---|
| Service | 3010 | 场景状态、MCP、HTTP/SSE、高德能力 |
| 后台 Agent | 3020 | DashScope 文本模型、后台 MCP、检索工具 |
| Gateway | 18888 | Realtime 模型、前台 MCP、后台 A2A |
| Client | 5173 | Gateway 地址、Service 地址、地图 JS 配置 |

前后台模型使用服务端配置，浏览器地图另有自己的 JS Key 与安全配置；服务侧地图调用使用高德服务 Key。四个进程的车机 ID 要一致，才能读取同一份业务状态。

在仓库根目录，复制示例配置、填写对应模型与服务参数后，可按原项目入口安装并启动：

```bash
cp examples/smart-cockpit/.env.example examples/smart-cockpit/.env.local
npm run example:smart-cockpit:install
npm run example:smart-cockpit
```

启动预检发现端口占用或配置缺失时会给出原因；外部模型、地图和搜索供应商的实际可用性仍需要运行时验证。安装与真实模型评测会访问外部服务，这里列出的是使用入口，本次文档整理没有执行这些操作。

## 扩展一个能力需要改哪里

新增座舱业务，一般在 Service 添加工具描述、参数结构和执行器，再接入工具注册与领域路由。它的状态写入和事件仍使用原有边界，界面按需增加呈现。前台与后台使用同一领域归属配置，避免两个执行面各维护一份工具实现。

接真实车辆或媒体平台，主要补充 Service 执行适配与反馈；换后台模型或执行服务，主要改 Agent 或后台 Adapter；换实时语音服务，使用 Realtime Provider；换车机界面，使用 Gateway 客户端协议和场景 HTTP/SSE。

这些边界让场景功能能够在复用框架的情况下独立演进。可靠性仍需落实到业务条件、超时取消、结果大小限制与错误返回。演示状态的多座舱隔离，也不能直接替代生产服务的身份认证和部署方案。

## 软件测试回答什么问题

软件测试通过确定性输入与测试替身验证程序契约。例如非法温度会不会被拒绝、SSE 是否推送新状态、订单缺少确认是否被阻止、温度条件持续满足是否反复提醒、后台取消是否结束活动执行。

这些测试可以验证程序逻辑与接口协作，但不会证明真实语音模型每次都选对工具。模型选择是另一项评测，需要给定用户输入、预期工具、参数和状态断言，并记录实际行为。

当前项目还有客户端 lint、生产构建和浏览器体验检查。代码测试、构建检查、视觉体验与模型能力各自验证不同层面的质量。

## 模型评测怎样形成证据

短用例集有 86 个 case、111 个交互轮，预期调用覆盖 34 种工具；一个 case 内的调用、参数、轮次、执行路径及指定状态断言全部正确，才算整例通过。长对话集有 10 组连续 50 轮会话，共 500 轮，其中需工具与无工具各 250 轮，按轮判断工具行为。

评测覆盖车控、导航、音乐和天气。闪购、自定义技能、后台长任务和语音回复质量没有被这两套准确率统一涵盖。

| 仓库已有记录 | 结果 | 怎样解释 |
|---|---:|---|
| Realtime-plus + Harness，短用例 | 84/86，97.67% | 受控数据集的整例通过率 |
| Realtime-plus + Harness，长对话 | 499/500，99.80% | 逐轮工具行为准确率，包含需工具与无工具轮 |
| 前台直调，平均工具返回时延 | 1.480 秒，90 个有效样本 | 语音输入结束至最后一个工具返回 |
| 后台委托，平均工具返回时延 | 3.560 秒，68 个有效样本 | 同样保留实时前台，增加后台委派链路 |

准确率引用仓库维护的 9 月结果记录；时延引用 2026-09-11 的历史报告。本次整理没有重跑它们。时延不含后续语音播放或实车动作，两组有效样本数量也不同，不能直接说成“用户总响应时间降低了某个比例”。

Harness 使用生产提示词与运行时保护，受控 Realtime 直连采用另一种装配。因此二者对比体现系统链路差异，不能仅归因于某一个模型或某一条保护规则。部分准确率记录的原始轨迹尚未公开，结果页明确记录了复现限制。

## 面试时怎样讲验证工作

可以先说：“验证分三层：软件契约测试、模型工具行为评测、工具放置时延对比。” 再说明数据集规模、统计单位和测量终点。引用数字时带上模型、Harness、样本和日期；如果是自己重跑的结果，再补自己的配置、轨迹和对照方式。这比只给一个“准确率 99%”更能说明工程判断。
