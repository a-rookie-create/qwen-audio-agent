# 11 · 项目介绍与简历表达

读完各模块后，介绍项目时可以沿“用户需求 → 整体方案 → 关键实现 → 设计取舍 → 验证与边界”展开。下面把它们连接成一次面试中的项目说明。

## 先用一分钟讲清项目

> 这个项目是基于 qwen-audio-agent 的智能座舱语音助手。它支持通过自然语音操作车控、导航、音乐和天气，也能在后台处理闪购与资料研究，同时保持前台连续交流。
>
> 系统由 React 客户端、Gateway、后台 Agent 和座舱 Service 组成。客户端处理声音与展示；Gateway 复用框架的实时语音会话和任务编排；Service 提供业务工具、规则和统一状态；后台 Agent 使用自己的模型完成多步工作。
>
> 实现上，前台通过 MCP 直接调用高频座舱工具，需后台执行的目标通过 A2A 交给 Agent。Service 用 HTTP/SSE 同步界面，并提供工作流与温度提醒；长期偏好复用框架的 Markdown 记忆能力。项目有软件契约测试、模型工具行为评测和工具返回时延对比。

随后补一句实现范围：“当前车控、媒体和订单使用演示状态，导航天气可连接高德，语音和研究接入模型与检索服务。” 这样听者能同时认识方案完整性与当前落地程度。

## 用一个场景把模块串起来

用户说“把空调调到 24 度，再导航去机场”，实时模型根据工具描述提取意图，Service 检查车控参数并规划路线，将实际结果返回模型，同时向 UI 推送状态。温度、路线和语音说明由同一次执行连接起来。

用户接着说“整理今天的汽车新闻”，前台把目标提交为异步任务，后台模型搜索、按需阅读来源并形成报告。前台仍能接受其他请求；结果完成后，框架按当前交互状态安排回流，详细报告与短口播分别呈现。

如果用户保存了“设定温度降到 20 度及以下提醒”，后续点击温度按钮也能触发规则。Service 用代码识别从条件外进入条件内，客户端转发场景事件，前台自然提醒。这个例子说明系统能够把语音输入、屏幕操作和环境变化纳入同一体验。

## 哪些技术点值得展开

**前后台分工**可以从执行路径讲：即时工具直接调用，持续工作异步委派。同一请求包含多个意图时按能力归属拆分。分工依据业务配置与工具可用范围，不能简单把“复杂的话”全部交给后台。

**工具与统一状态**可以从闭环讲：模型提出动作，程序校验并执行；HTTP 与 MCP 共用执行器，SSE 将事实同步到 UI。新增业务主要扩展 Service，减少模型、界面与业务实现之间的耦合。

**后台 Agent**可以从工具循环讲：每轮模型选择操作，实际结果回填，执行器限制轮数与次数，传递取消，交付报告与摘要。引用来源及读取状态，让新闻结果的依据可以追溯。

**技能与记忆**可以从生命周期讲：工作流保存步骤，模型按需执行；事件规则确定性触发，模型负责表达；长期记忆持久化，车辆状态和后台历史另有存储。用户的当前要求与真实查询结果仍优先影响本次回答。

## 简历描述怎样落到个人工作

项目简介可以写成：

> 基于 qwen-audio-agent 的智能座舱语音交互项目，组合 Realtime 语音模型、MCP 场景工具与 A2A 后台 Agent，实现语音业务操作、异步任务执行、环境提醒与座舱界面联动。

个人工作则需要具体到已经做过的部分。可以从以下方向选择，并填写自己的实际实现与验证结果：

- **业务工具方向：**设计或扩展 `[具体领域]` 工具参数、执行器与状态反馈，处理 `[具体校验或异常]`，通过 `[自己的测试或演示]` 验证。
- **语音与编排方向：**接入或调整 `[模型/前后台执行面]`，实现或改进 `[具体交互、取消、播报或任务行为]`，记录 `[自己的对照结果]`。
- **客户端方向：**实现或优化 `[地图/3D 车辆/任务/记忆面板]`，通过结构化状态与事件同步 `[具体交互]`。
- **工程验证方向：**构建或复现 `[评测集与链路]`，明确统计单位、样本与测量终点，分析 `[自己观察的错误或取舍]`。

这类描述把“使用了什么框架”与“完成了什么工作”连接起来。仓库的历史成绩可作为项目背景；写成自己的成果时，需要对应自己实际完成的实验与记录。

## 常见追问可以怎样回答

问“为什么要两个模型”，可以从交互与工作节奏回答：实时模型维持语音交流，后台文本模型用工具循环完成持续工作，任务事件把结果接回来。两个模型各自有上下文，交接目标需要保留必要约束。

问“怎么减少模型乱操作”，可以说明工具目录限定能力，参数设计表达业务意图，程序验证数值与阶段，订单检查预览和确认，提醒路径禁止调用工具，执行还有超时与预算。然后承认模型选择仍需要受控评测与真实体验验证。

问“有哪些不足与下一步”，可以选择一项真实边界展开：接真实车辆反馈、持久化业务状态、接商业媒体或订单系统、完善授权与失败恢复，或者扩大真实语音与混合意图评测。说明要改哪一层、怎样验证，就能体现对当前架构的理解。

如果能沿这些场景讲清职责、数据来源和技术取舍，就已经具备介绍完整方案所需的理解。需要回答更细的追问时，再回到对应模块与末尾依据查看。
